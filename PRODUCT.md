# Humanette

## Register

product

## Users

Developers and agent-automation authors evaluating an npm package beside their editor. They need to understand the effect, install it, and integrate real browser input without studying marketing copy. They work in both bright daytime and dim evening environments.

## Product Purpose

Make browser actions easier to follow in product demos with legible contextual cursors, natural movement, and press/hold/release feedback. The public package and documentation are Playwright-first, with native locator targeting and a workbench for tuning. The shared visual runtime powers site previews internally. Humanette is not a video recorder and does not guarantee a capture frame rate.

## Brand Personality

Clear, capable, personable. Small moments of delight should demonstrate the package, never delay access to it.

## Anti-references

Avoid grand startup positioning, vague poetic claims, oversized marketing heroes, repetitive feature cards, decorative dashboard chrome, and technically misleading visual simulations presented as real automation.

## Design Principles

1. Show the effect before explaining the internals.
2. Put installation and a usable example within easy reach.
3. Distinguish visual playback, real browser input, and recording.
4. Respect the reader's time through concrete copy and progressive disclosure.
5. Make light and dark themes equally usable; preserve the tuning workbench and native cursor comparisons.

## Accessibility & Inclusion

Aim for WCAG AA contrast, visible keyboard focus, labeled controls, responsive layouts, and reduced-motion support. Motion is a demonstration feature, with explicit playback or pause controls. Color must not be the only state indicator.
